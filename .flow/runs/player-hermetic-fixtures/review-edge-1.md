### F1 [major] The stale-callback probe never puts A's failure into the window it claims to check
- Where: app/src/androidTestInstrumentation/kotlin/com/kino/puber/ui/feature/player/vm/PlaybackControllerStaleCallbackTest.kt:64-65 (window: app/src/main/java/com/kino/puber/ui/feature/player/vm/PlaybackController.kt:260-264, :499-519)
- Problem: The defect from the spec's research would need A's parse error to be already queued on the main looper, or in flight from the playback thread, at the moment `switchStream(B)` runs on main. Then `onPlayerError` would attribute it to `currentStreamUrl`, which now holds B. The test does it the other way round. It calls `switchStream(B)` while A's body is still held at the gate, and opens the gate only after `runOnMainSync` returns. By then `setMediaItem`/`prepare` have been posted to the playback thread, and that thread cancels A's loader. So the order of events is a race between the gate opening on the test thread and the loader being cancelled on the playback thread. In the usual case A's body is never parsed and no error is ever produced, so the test passes whether or not the attribution bug exists. The control test (`delayedFailure_reportsStreamFailure_whenStreamIsNotSwitched`) only shows that the failure path exists without a switch. It does not show that the switch test ever reaches the window. The evidence file says the control "shows the probe is not vacuous", and `player-callback-gate` is not opened because of that conclusion.
- Failure scenario: Suppose a production change widens the window, for example by posting `onStreamFailure` through `mainHandler` like `SeekStallRecovery` does, without a URL check. The A load is still cancelled before its body is parsed. No `StreamFailure`/`Error` follows the mark, the test stays green, and AC-5 records "not reproduced" again. 10 of 10 green runs cannot tell "absent" from "never exercised".
- Fix: Make the failure happen before the switch, inside one main-thread turn. In a single `harness.onMain { ... }` block:
  1. Open the gate.
  2. Spin, with a bound, until `server.requestJournal` shows the stream-a entry with `outcome == Completed(200)`, plus a short wait for the playback thread to parse and post the error.
  3. Call `switchStream(B)` in the same block.
  Any `onPlayerError` that is already posted to main is then delivered after the switch, against `currentStreamUrl == B`. Keep the current variant as a second case if you like. Change the evidence wording so it states which ordering was exercised.
