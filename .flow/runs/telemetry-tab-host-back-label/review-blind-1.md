### F1 [minor] Frozen tab root names a tab that is gone when the tab is switched while the host is covered
- Where: app/src/main/java/com/kino/puber/core/ui/navigation/component/NavTelemetry.kt:41-49 and app/src/main/java/com/kino/puber/core/ui/navigation/component/FlowComponent.kt:593-597
- Problem: `unbind` saves the covered tab's root (`navigator.items.firstOrNull()`) and keeps it for the host until something binds again. It assumes the host will come back showing that same tab. But `MainVM` keeps collecting `contentPreferences` and `menuTabsChanges` while the host is covered (MainVM.kt:55-60). From there, `onMenuTabsChanged` and `onContentPreferencesChanged` can call `tabRouter.openTab(<another tab>)`. Nobody consumes that Open until the host is composed again, so the root `Back` is recorded first, with the saved root.
- Failure scenario: The user is on the Anime tab and opens device settings from the host (`router.navigateTo(deviceSettings())`, a root push). They hide anime or remove that menu section, so `selectedTab` changes and `openTab(Home)` is replayed later. They press Back. The `Nav(BACK, to=<Anime tab root class>)` event is recorded and `Telemetry.screen` becomes that class, even though that screen is never shown again. Only then does the replayed Open record `TAB` from Anime to Home. Before this diff the Back recorded the neutral `MainScreen` fallback. Now it records a specific wrong screen.
- Fix: Drop the saved binding when the host's tab changes while it is covered. For example, `TabHostTelemetry` could expose `invalidate(host)`, and `TabRouter.openTab` (or the `TabComponent` collector, if it is still alive) would call it. Another option is to save the pending tab's root: the latest `TabCommand.Open` in the router's replay cache. If neither fits, record this limitation next to the existing note about tab-stack-lost-on-root-push.

### F2 [nit] A saved binding keeps a dead host and its tab root alive in a global object
- Where: app/src/main/java/com/kino/puber/core/ui/navigation/component/NavTelemetry.kt:43-46
- Problem: Before this diff, `unbind` set `binding = null`. Now it leaves a `Binding` that holds strong references to `handle.host` and to the saved screen. Only a later `bind` replaces it. When the host is popped for good (logout → `NewRoot(auth)`, or `FinishFlow`), the old `MainScreen` and its tab root screen stay reachable from the `TabHostTelemetry` singleton until a new host binds. The `host ===` identity check stops wrong attribution, but not the retention.
- Fix: Keep the saved screen's class (`telemetryClassOf(frozen)`) instead of the screen itself, and hold the host through a `WeakReference`. Alternatively, clear the saved binding when the root navigator leaves the host.

### F3 [nit] The two-argument `bind` overload is now used only by tests and behaves differently from production
- Where: app/src/main/java/com/kino/puber/core/ui/navigation/component/NavTelemetry.kt:35
- Problem: `bind(host, top)` passes `top` as `reappearingTop`, so `unbind` saves the live top. Production (`FlowComponent.kt:593`) saves the root. Several unit tests (`disposedBindingKeepsTheTopForTheSameHost`, `tabLocalTopIsFrozenAtUnbind`, `frozenBindingOfHostADoesNotLeakIntoFreshHostB`) use this overload. They pass with "top" semantics that production never uses, so they cannot catch a regression in the root-saving path. Only `unbindFreezesTheReappearingTopNotTheLiveTop` checks that path.
- Fix: Remove the two-argument overload and make the tests pass `reappearingTop` explicitly, so they exercise the production behaviour.
