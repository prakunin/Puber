### F1 [major] Turning the session log on in Device Settings still records Back as `Main`, and the new replay guard means nothing corrects it afterwards
- Where: /home/user1/orca/workspaces/Puber/telemetry-tab-host-back-label/app/src/main/java/com/kino/puber/core/ui/navigation/component/NavTelemetry.kt:41-49 (`unbind` only freezes when `Telemetry.isEnabled`), together with /home/user1/orca/workspaces/Puber/telemetry-tab-host-back-label/app/src/main/java/com/kino/puber/core/ui/navigation/component/TabComponent.kt:118 (`if (from !== event.tab)`).
- Problem: The binding is frozen only if telemetry is on when the host is covered. The session-log toggle is in `DeviceSettingsVM`. The rail Settings item opens that screen with a root push (`MainVM.onSettingsClick` -> `router.navigateTo(screens.deviceSettings())` -> `DeviceSettingsFlowScreen`), so the host is covered there too. When the user enables telemetry from that screen, the host was covered while telemetry was off: `unbind` set `binding = null` and froze nothing. Before this diff, the replayed `TabCommand.Open` recorded `nav tab X->X` when the host came back, which reset `Telemetry.screen` to the tab. The new identity guard skips that replay, because it is the same `PuberTab` instance (AC-4). Nothing else resets the label.
- Failure scenario: Session log is off. On the Home tab, the user opens Settings from the rail (host covered, binding cleared), turns the session log on, then presses Back. The log gets `nav back from=DeviceSettings… to=Main`, and `Telemetry.screen` becomes `MainScreen`. The host comes back, the live bind happens, but no record follows: the replay is suppressed. Every frame, key and memory sample stays tagged `Main` until the user's next navigation. This is the defect the run fixes, on the most common way to start a session, and the replay guard makes it last longer than it did on base.
- Fix: Freeze `handle.reappearingTop()` in `unbind` whether or not telemetry is enabled. That is one snapshot read and one small `Binding` per cover, and it still records nothing, so AC-9's wording ("no binding or freeze work records anything") holds. Update `unbindWithTelemetryOffKeepsNoFrozenTopAndNeverReadsIt` to match. If AC-9 must stay strictly read-free, the alternative is to let the replayed Open record (or set `Telemetry.screen`) when `Telemetry.screen` is the host's class. Either way, add a JVM case: unbind while off, enable, Back to the same host -> `HomeScreen`.
