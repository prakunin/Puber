### F1 [minor] Lowering the media cache to 256 MB does not shrink an existing cache, and with the main player read-only it may never shrink
- Where: app/src/main/java/com/kino/puber/data/di/modules.kt:79 (MEDIA_CACHE_SIZE_BYTES), app/src/main/java/com/kino/puber/ui/feature/player/vm/PlaybackController.kt:417
- Problem: `LeastRecentlyUsedCacheEvictor` frees space only when a new file is written (`onStartFile`). Its `onCacheInitialized` does nothing, so a `SimpleCache` that already holds up to 512 MB stays that size when the app starts with the lower cap. The same diff turns off cache writes for the main player (`writeToCache = false`). That leaves the next-episode warm-up as the only writer, and only the warm-up can trigger eviction.
- Failure scenario: a user upgrades with a full 512 MB media cache from earlier playback and then watches only films, so no next-episode warm-up ever runs. Nothing is written to the cache, the evictor never runs, and the app keeps about 512 MB on disk for good. The storage bound this change sets never applies to that user.
- Fix: after the `SimpleCache` is built (off the main thread), evict down to the new cap once. Remove the least recently used spans (`cache.keys` / `getCachedSpans` sorted by `lastTouchTimestamp`, then `removeSpan`) until `cacheSpace <= MEDIA_CACHE_SIZE_BYTES`. Doing it in `CachedPayloadSweeper`'s first sweep after startup is enough.
