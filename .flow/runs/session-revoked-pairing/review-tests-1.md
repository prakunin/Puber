### F2 [minor] Nothing pins "emit before clear" in `onSessionExpired`, and the cold-start fix depends on it
- Where: `app/src/main/java/com/kino/puber/data/api/KinoPubApiClient.kt:268-273`; the reader is `app/src/main/java/com/kino/puber/ui/feature/root/vm/LauncherVM.kt:37,57-58`
- Problem: `LauncherVM` reads the access token through `cryptoPreferenceRepository.getAccessToken()`, outside `sessionLock`. It then checks `sessionEventBus.hasPendingEnd`. Its decision is only right if the end is already pending by the time the token reads as null. So the `emit` has to come before `clearAccessToken()`. No test fails if the two lines are swapped. The client tests only check the final state (tokens null, one event), and `LauncherVMTest` seeds the bus before start.
- Failure scenario: someone moves `sessionEventBus.emit(...)` after the clears. On a cold start of the banned stage app, `AppStartup` gets the 403 on IO while `LauncherVM` reads the token. The Launcher sees null with nothing pending and opens `auth()` with no reason. The handler then re-roots to `auth(Blocked)`. That is the double re-root from qa round 1, and Auth briefly shows without the blocked line.
- Fix: In `KinoPubApiClientSessionEndTest`, make `FakePrefs.clearAccessToken()` record `bus.hasPendingEnd` at the moment it is called. Then assert that value is `true` in `aUserBannedRefusalClearsTokensAndEmitsBlocked`. For that, the fake needs a reference to the bus, or the bus can be passed to its constructor.
