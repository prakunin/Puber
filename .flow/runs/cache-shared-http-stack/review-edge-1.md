### F1 [major] A single failed DoH query now fails every request to that host for about 10 s, which can trigger an unwanted mirror switch
- Where: /home/user1/orca/workspaces/Puber/cache-shared-http-stack/app/src/main/java/com/kino/puber/data/api/network/HttpStack.kt:18 (`val dnsCache = DnsCache()`)
- Problem: The default `DnsCache()` also caches failed lookups. I checked `RealDnsCache$CacheQuery.onFailure` in the okhttp-android 5.5.1 bytecode: it stores a `Result.Failure` holding the `IOException`. That entry expires after `failureTimeToLive` (10 s by default) and revalidates at 8 s. Until then every lookup of the host gets the same exception back without querying again. At base, `DnsOverHttps` had no cache, so each attempt queried live. Three parts of the code assume a fresh lookup on every attempt:
  - Ktor `HttpRequestRetry` with `MAX_RETRIES = 3` (`KinoPubApiClient.kt:187-188,1193`). Its default delays add up to well under 10 s, so all retries now fail from the cached entry.
  - `reportIfDomainUnreachable` (`KinoPubApiClient.kt:1060-1061`). It treats any `IOException` that is not `NoConnectivityException` as "host unreachable" (`ConnectivityPlugin.kt:33`) and calls `markUnreachable(domain)`.
  - `autoResolveWorkingDomain` (`ApiDomainInteractor.kt:118-145`). It probes the current endpoint first through `HttpEndpointProbe` on the same client. That probe resolves from the cache, gets the cached failure and returns false. The method then moves on to the next built-in endpoint, a different host that gets a fresh lookup.
- Failure scenario: The TV wakes from standby. The network reports INTERNET capability but is not routing yet, or dns.google times out once. Home's load calls KinoPub, the DoH query fails and the failure is cached. All 3 retries fail from the cache, and the domain is marked unreachable. The next Home load (ON_RESUME or a retry) runs within 10 s. `autoResolveWorkingDomain` probes the current domain and gets the cached failure, then probes `api.alador.space` live, which succeeds. Result: `changed = true`, the mirror is saved to preferences, Home rows are cleared and the user sees the "domain switched" toast. All of this followed a sub-second resolver blip that at base would have been absorbed by a retry or the fresh probe.
- Fix: Build the cache with `DnsCache(failureTimeToLive = Duration.ZERO)`. The constructor only requires `>= 0`, so ZERO is accepted, and positive answers stay cached by TTL. Add a `DnsOverHttpsFactoryTest` case: a fake DoH server whose first call throws `IOException`, then two lookups, expecting 2 queries.
