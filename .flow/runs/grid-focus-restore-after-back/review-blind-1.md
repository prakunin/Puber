### F1 [major] The focused card is lost on Back when the details screen reports a content change
- Where: app/src/main/java/com/kino/puber/ui/feature/collections/detail/component/CollectionDetailScreenContent.kt:52-65, app/src/main/java/com/kino/puber/ui/feature/collections/detail/vm/CollectionDetailVM.kt:98-101 and :69-70
- Problem: Two pieces of state live inside the `is Content` branch. One is the remembered focused card id (`rememberReconciledItemFocus`, which uses `rememberSaveable`). The other is the grid's scroll position (the default `rememberLazyGridState`). When details returns a non-empty `ContentChangeSet`, `onReturnedContentChanges` calls `loadItems()`. That sets the state to `Loading`, so the Content branch leaves composition and both saveable values are thrown away. When `Content` comes back, `initialItemId` resolves to `items.firstOrNull()`. The `LaunchedEffect(isTargetRow, contentFocusActive)` then focuses the first card, and the grid starts again at the top.
- Failure scenario: Open a collection and move to card 8 (third row). Open details and toggle bookmark or watched. Press Back. The grid reloads, card 1 is focused and the list is scrolled to the top. The fix restores focus only when Back carries no change, which is the case the in-place tests cover. They never go through `Loading`.
- Fix: Keep the `Content` subtree composed while reloading after a return. Either refresh in place: replace the items without emitting `Loading` when the state is already `Content`. Or move the focus id and the `LazyGridState` above the `when (state)`. Add a test that goes Content -> Loading -> Content and expects the same card to be focused.

### F2 [minor] Opening a collection now focuses the first card automatically
- Where: app/src/main/java/com/kino/puber/ui/feature/collections/detail/component/CollectionDetailScreenContent.kt:59-65
- Problem: `rememberReconciledItemFocus(isTargetRow = true)` seeds the focused id with the first item. Its `LaunchedEffect(isTargetRow, contentFocusActive)` then calls `requestFocus()` as soon as Content first composes. Before this change the screen did not grab focus by itself. Nothing in the diff says this changed, apart from one test (`collectionDetailFocusesTheFirstCardOnFirstLoad`). The same effect fires every time `contentFocusActive` goes from false to true, for example each time the context menu or the side rail closes. Each time it re-requests the remembered card.
- Failure scenario: The user opens the context menu, then dismisses it with Back. Focus is sent to the remembered card one frame later. This is probably wanted. But if the menu action started a navigation (Watch -> player), a focus request still fires on the screen being left, during the transition.
- Fix: Say in the change description that this is intended. Optionally skip the post-dismiss request when the dismissal came from an action that navigates.
