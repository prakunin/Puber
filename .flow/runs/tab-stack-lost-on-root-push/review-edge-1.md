### F1 [minor] A tab refreshed while the host is covered briefly shows the restored stack on Back, and the Back telemetry line names it
- Where: `app/src/main/java/com/kino/puber/core/ui/navigation/component/FlowComponent.kt:591-596` (`reappearingTop = { navigator.lastItemOrNull }`) together with `TabFlowNavigator`'s `LaunchedEffect(contentInstanceKey)` at `:604-610` and `TabComponent.kt:117-131` (replayed `TabCommand.Open`)
- Problem: The tab host is covered, and during that time the selected tab's `refreshVersion` is bumped. `MainVM.onContentPreferencesChanged` does this when "show anime" changes and the selected tab is in `ANIME_FILTERED_TABS`. The resulting `openTab` is buffered in `TabRouter` and only delivered after the host is composed again. On Back, the first frame therefore composes the old `PuberTab`, and the holder restores its full stack (for example ShowAll). The replayed Open then changes `contentInstanceKey`, and `replaceTabRootIfChanged` resets the tab to its root. `unbind` froze the live top (ShowAll), so the root Back is recorded as `to=ShowAll` while the user ends on the tab root. A later `TAB` line then corrects `Telemetry.screen`. Before this change, the frozen screen was the root, which matched the final screen. Spec R6 accepts that the refresh lands on the new root. It does not mention the visible ShowAll-then-root jump or the wrong Back line. On the ShowAll that is about to be replaced, the new focus-restore effect also starts and requests focus on a card that is disposed one frame later.
- Failure scenario: Movies tab → Show all → Settings hotkey (root push) → toggle "show anime" → Back. The ShowAll grid flashes, then the Movies root appears. Telemetry shows `nav back from=DeviceSettingsFlow to=ShowAll` followed by `nav tab ... to=ContentList`.
- Fix: In `TabComponent`, drop or ignore saved subtree state for a tab key whose `contentInstanceKey` changed while the host was covered. One way is to call `subtreeStateHolder.removeState(tab.key)` when an Open arrives whose `contentInstanceKey` differs from the session's. The other option is to record this as an accepted R6 consequence (flash plus one stale Back line) in the spec.

### F2 [minor] The ShowAll focus restore has no fallback when the opener card leaves the list after Back
- Where: `app/src/main/java/com/kino/puber/ui/feature/showall/content/ShowAllScreenContent.kt:84-97,130-131`
- Problem: Restore targets only `restoreId`. It is captured once, attempted for 3 frames, and any failure is swallowed by `runCatching`. Before this change the grid did not survive a root push. Now it does, so `ShowAllVM.onReturnedContentChanges` (`ShowAllVM.kt:110-115`, `refreshFirstPage()` on a non-empty `ContentChangeSet`) runs against a live grid right after Back. With hide-watched on, that reload removes the card that was just watched. Either the restore lands on that card and the async reload then removes the focused node, or the card is already gone and the requester is never attached. Nothing picks a neighbour. Rows handle the same case with `resolveFocusedItemId` in `rememberReconciledItemFocus` (`FocusTargetState.kt:40-90`). qa-report AC-2 only checked returns where the list did not change.
- Failure scenario: Concerts → Show all with "hide watched" on → card → Details → play to the end → Back → Back. The reload drops the opener, so focus is cleared or jumps to wherever the default focus search lands, possibly the rail, instead of a neighbouring card.
- Fix: Keep the focused item's index next to its id. When `restoreId` is missing from `state.items`, or disappears after restore while the grid has focus, request focus on the item at `min(index, items.lastIndex)`. Alternatively, reuse `resolveFocusedItemId` from `FocusTargetState.kt`.
