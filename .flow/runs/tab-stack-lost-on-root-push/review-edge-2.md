### F1 [minor] A reload that lands during the entry restore's three frames leaves no card focused
- Where: `app/src/main/java/com/kino/puber/ui/feature/showall/content/ShowAllScreenContent.kt:194-196,198-204` (`inGrid` gate at :200, flag at :178)
- Problem: `restoreOnEntry` works out `restoreId` once, when the memory is created, and then tries `restoreFocus` for up to three frames. If a new `items` list without the opener arrives inside that window, `restoreId` still names the opener. The requester is then attached to nothing, and each attempt fails silently through `runCatching`. The fallback in `restoreWhenFocusedCardLeft` is skipped too, because `inGrid` is still `false`: the grid never received focus on this entry. On re-entry, `rememberFocusRequesterOnLaunch` has `isFocusRequested == true` saved, so nothing else takes focus either.
- Failure scenario: In Show all with "hide watched" on, the user leaves through a root push (Settings) or Details while a hide-watched or settings `refreshFirstPage()` is still in flight, then presses Back. The page is published within about 50 ms of ShowAll being composed again, without the opener. The entry attempts target a card that no longer exists, the neighbour fallback does not run, and no card is focused. This is unlikely because the timing window is about three frames. The common orders work: a reload that finished while covered is handled on entry by `resolveRestoreId`, and a reload that arrives after a successful entry restore is handled by the live path.
- Fix: Inside `requestRestoreFocus`, before each attempt, set `restoreId = resolveRestoreId(lastFocusedId.value, lastFocusedIndex.value, items())`. Alternatively, let `restoreWhenFocusedCardLeft` also run while the entry restore has not yet succeeded, for example with a `restoring` flag next to `inGrid`.

I checked the following against the increment, and each one holds:
- **Fix #1:** `contentFocusActive` is read through `rememberUpdatedState` on every attempt (:149, :209). `LocalContentFocusActive` is a `staticCompositionLocalOf` provided from `drawerState` (`MainScreenComponent.kt:138`), so a change to it recomposes the subtree and updates the value. When the rail opens mid-retry, the loop stops instead of pulling focus back.
- **Fix #2, card already gone before re-entry:** `resolveRestoreId` falls back to `items[index.coerceIn(0, lastIndex)]`.
- **Fix #2, card leaves a live grid:** `refreshFirstPage` keeps the content on screen (`refreshPagingKeepingContent`, `ContentListPagingVM.kt:104-108`), so the body and its saveable memory stay composed. `onGridFocusChanged(false)` sees the new list, because `rememberUpdatedState` is applied before lazy measure disposes the item, so `inGrid` stays `true`. `LaunchedEffect(items)` then moves focus to the neighbour. Note that this ordering is argued from Compose phases and has only the androidTest case behind it. Those instrumented cases were not run on a device (see the plan note).
- **Paging and load-more:** an append restarts `LaunchedEffect(items)`, but the focused id is still in the list, so it does nothing. A restart in the middle of a restore re-resolves from `lastFocusedId`, which has not changed, so the restore still happens.
- **Empty list:** the state becomes `ShowAllViewState.Empty`, the body leaves composition, and `resolveRestoreId` also guards `items.isEmpty()`.
- **Items reordered:** the focused card is still present by key, so nothing restores. `lastFocusedIndex` can be stale until the next focus event, but every way back into the grid passes through `onCardFocused` again.
- **Rail open:** moving into the rail clears `inGrid` while the card is present. If the card is removed while focus is lost, `inGrid` can stay `true`, but every later attempt is gated by `contentFocusActive == false` while the drawer is open, so no focus is stolen.
- **Process death:** `lastFocusedIndex` is a saveable `Int`. If the body first composes after `Loading`, it still reads the restored registry values. If the opener sits beyond the reloaded first page, focus goes to the last loaded card, which is the clamped index.
- **Focus stolen on unrelated list updates:** remap, saved-flag updates and appends all leave the focused id in the list, so `restoreWhenFocusedCardLeft` does nothing.
