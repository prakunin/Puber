### F1 [minor] After a card whose poster fails to load, the next card change slides out an older card's picture
- Where: app/src/main/java/com/kino/puber/core/ui/uikit/component/details/VideoItemGridDetails.kt:640-648 (`PosterStill` onSuccess/onError) and :715-729 (`rememberPosterTransition`)
- Problem: `holder.shownImage` changes only in `onSuccess`. It is cleared only when `heldUrls` is empty. When every URL of a card's poster fails, `onError` leaves `shownImage` holding the image of the card shown before it. `SkeletonAsyncImage` sets its alpha to 0 when `isFailed`, so the frame on screen is empty. On the next change, `rememberPosterTransition` builds the outgoing layer from that stale image, so a poster that was not on screen slides out.
- Failure scenario: card Z shows its poster. The user presses Right to A, whose primary and fallback URLs all fail. The outgoing Z picture stays for the 3 s timeout (R9 accepts this), then the frame goes empty. The user presses Right to B: Z's poster appears at full alpha and slides out toward the start while B enters. Z is two cards back and was never A's picture. Failing poster URLs do happen in this project, because the `detail-poster-fallback-empty-frame` run exists for that case.
- Fix: in the still's `onError`, when `urlIndex >= heldUrls.lastIndex` (the last URL failed), set `transition.shownImage = null`. That way no record is built from an image that is not on screen.
