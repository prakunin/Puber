### F1 [major] A text-less report is always treated as transient, so the picker can show a subtitle as selected when the stream has no text tracks
- Where: app/src/main/java/com/kino/puber/ui/feature/player/vm/PlayerVM.kt:534-541 (and 557-560)
- Problem: Commit 36da8957 treats every non-null report with no non-Off rows as transient. It keeps `previous.subtitleTracks` and the pick, and sends nothing. Nothing tells a truly transient report apart from a stream that really has no text groups: `buildSubtitleRows` never emits an Off row, so "text-less" just means `textGroups` is empty. The transient premise is unverified on a device (plan line 858). The QA evidence suggests the opposite: the repro waited 5-10 s on 720p and saw only `Off`; under the old code any later report with text groups would have rebuilt the rows through `merge`, so on that stream no text group arrived during the whole wait. Manual quality uses `url.hls` (PlayerInteractor.kt:243), while Auto uses `hls4` first (PlayerInteractor.kt:232), and Auto falls back from `hls4` to `hls`. So the stream itself can change between one that has subtitle renditions and one that has none.
- Failure scenario:
  - (a) Item with no side-loadable API subtitles, subtitles only from the `hls4` manifest. On Auto with `English` (manifest row) selected, viewer picks 720p. The `url.hls` stream reports audio and no text groups, persistently. The VM keeps the old rows with `English` checked, but no text renders; picking another row only sets a pending pick that never matches. Before this commit the picker correctly showed only `Off`.
  - (b) Next episode with a manual quality kept: `publishPreparedContent` puts the new API rows in place; the first report is text-less, so `rows = previous.subtitleTracks` (unmerged API rows). `restoreTrackPreferences` runs on those rows and consumes `tracksRestoredForCurrentMedia`; it shows the saved `Russian` as selected, but nothing plays.
  - (c) During a link refresh (line 488), `apiSubtitleTracks` is replaced; a text-less report keeps rows built from the old link URLs, so picking one sends the old URL.
- Fix: decide "transient" in the controller. When `currentItemHasSideLoads` is true, side-load text groups must appear once the item is prepared, so pass `null`/"unknown" for the subtitle part while `textGroups` is empty and the VM keeps its rows. Otherwise report the empty list as real: the VM merges it to `[Off]` but does not send Off to the controller, keeping `pendingSubtitleTrack` alive so the pick returns when text groups come back (e.g. back on Auto). Do not set `tracksRestoredForCurrentMedia` on a transient report. Tests: a report that stays text-less with no side-loads; a first report of a new media that is text-less.

No other findings survived: findRendition with both labels null still needs sameSubtitleLanguage (false for blank, SubtitleLanguage.kt:9) and a single rendition; HLS->progressive fallback reports null; group+index guard fine; forced flag on manifest rows fine; blank-url filtering applied at mapper, factory and both controller sites.
