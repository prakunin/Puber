### F1 [minor] No unit test covers the controller's D9 Off check
- Where: app/src/main/java/com/kino/puber/ui/feature/player/vm/PlaybackController.kt:569 (`if (track == null || track.isOff)`)
- Problem: D9 is one of the three highest risks (score 9): a manifest-only row with `url == ""` must not turn subtitles off. The unit tests check two things: the `isOff` extension (`SubtitleTrackUIStateTest.isOff_isFalse_forManifestRowWithEmptyUrl`) and that the VM passes a non-Off row to a mocked controller (`PlayerVMTrackSelectionTest.selectSubtitle_manifestOnlyRow_isDelegatedNotTreatedAsOff`). The line that actually had the bug is the Off check inside `PlaybackController.selectSubtitle`, and no unit test reaches it.
- Failure scenario: someone puts `track.url.isEmpty()` back in `selectSubtitle`, or adds a `url` check next to `isOff`. All 1561 unit tests stay green, but picking a manifest-only language (AC-2) clears the override and disables text. Only device check D-2 would catch it, and that has not run yet (the run is in stage `verify`, and `docs/superpowers/evidence/` has nothing for this run).
- Fix: either move the Off/target decision of `selectSubtitle` into a pure helper, for example `SubtitleTrackSelector`, and test it with an empty-url manifest row, or record in the spec that D-2 is the only guard for this line and that it is mandatory.

### F2 [minor] `buildSubtitleRows` / `findRendition` (D5 row building) have no tests
- Where: app/src/main/java/com/kino/puber/ui/feature/player/vm/PlayerTextTracks.kt:20-80
- Problem: This code decides `playerTrackId`, `playerTrackUri` and `isForced` (the OR of format and rendition flags), and fills in the language and `descriptiveLabel` from the rendition. Its rendition matching is "stripped id, then label + language, never position". All merger and VM tests feed rows built by hand, so they assume this code is right. Only `subtitleSourceId` (the prefix and `fromManifest` rule) is tested, in `SubtitleTrackIdentityTest`. Risk R4 (score 6) depends on `playerTrackUri` being set here; without it the API linking and the saved-URL restore (AC-7) both miss. The spec dropped Media3 types from unit tests because of `Uri`. But `Format.Builder`, `TrackGroup` and `Tracks.Group` are plain Java, and `HlsMultivariantPlaylist.Rendition` accepts a null url. So matching on id and label could be tested on the JVM, with only the `uri` assertion left to the device.
- Failure scenario: someone compares the rendition id with the unstripped `format.id`, or a positional fallback (`renditions.getOrNull(trackIndex)`) comes back. Manifest rows then get no `playerTrackUri`, or the wrong one. Merged rows lose their API `url`, the restore by saved URL fails, and the unit suite stays green.
- Fix: add `PlayerTextTracksTest`, built from `Format.Builder` / `TrackGroup` / `Tracks.Group` and renditions with a null url. Cover: a rendition matched by stripped id when merged; a fallback on label + language; no match when two renditions are ambiguous; no positional pick; forced taken from the rendition flags. If the JVM really cannot build these types, say so in the spec and name the device check that covers it.

### F3 [minor] The R5 loop test only counts the restore's Off re-apply, not a re-send after a real pick
- Where: app/src/test/kotlin/com/kino/puber/ui/feature/player/vm/PlayerVMTrackSelectionTest.kt (`tracksUpdated_identicalRepeatedReports_sendSingleReSelect`, `tracksUpdated_keepsSelectedRow_whenSameMergedRowStillExists`)
- Problem: In `identicalRepeatedReports` the single `selectSubtitle` comes from `restoreTrackPreferences`, which re-applies Off on the first report. So the test only proves Off->Off sends nothing. `keepsSelectedRow_whenSameMergedRowStillExists` does pick a real row (rus.vtt) and repeats the report, but it checks only the state and never counts controller calls. The case the spec describes ("re-send ... must stop after one") is not tested on a non-Off row, and neither is a third report after the re-send in `selectedRowReordered_followsRowToNewIndex`.
- Failure scenario: the re-find or merge stops treating equal rows as equal for a picked row. `row != previousRow` is then true on every report, and `selectSubtitle` is re-sent on every `onTracksChanged` for as long as playback runs. Every test still passes, because none of them counts calls after a user pick.
- Fix: in `keepsSelectedRow_whenSameMergedRowStillExists`, call `clearMocks(playbackController, answers = false)` after the pick and `verify(exactly = 0) { playbackController.selectSubtitle(any()) }` after the repeated report. In `selectedRowReordered_followsRowToNewIndex`, send the reordered report once more and assert the count is still exactly 1.
