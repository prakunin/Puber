### F1 [minor] Rebuilding the same media now loses the viewer's subtitle pick when the stream reports no audio group
- Where: app/src/main/java/com/kino/puber/ui/feature/player/vm/PlaybackController.kt:372-374, with PlaybackController.kt:852-854 and PlayerVM.kt:211-221, 862-884
- Problem: `prepare()` now always sets `pendingSubtitleTrack` to null. It is called both for new media and for rebuilds of the same media (`selectBufferPreset` and `toggleFastDns` go through `initializePlayer`). On a rebuild, putting the viewer's live pick back now depends only on the VM's restore in `onTracksUpdated`. That callback never fires when `notifyTracksUpdated` returns early because there are no audio groups. Before this fix, the surviving pending pick was re-applied by `onTracksChanged` -> `applyPendingSubtitleSelection`. So the fix swaps the failure: it no longer turns text on wrongly for new media, but it now drops text wrongly when the same media is rebuilt. `prepare()` disables text by default (`setTrackTypeDisabled(TEXT, true)`), so nothing turns it back on.
- Failure scenario: a stream that exposes no audio TrackGroup, with subtitle "Русский" picked, and the viewer changes the buffer preset or toggles Fast DNS. The player is rebuilt with text disabled, the VM restore never runs, and the picker still shows "Русский" while no subtitles are drawn. It is very unlikely on KinoPub content, which nearly always has audio. This is the same trigger the original #1 needed.
- Fix: clear the pending pick only when the media changes, not on every `prepare()`. For example, in `selectBufferPreset` and `toggleFastDns`, have the VM call `playbackController.selectSubtitle(currentRow)` right after `initializePlayer`. `exoPlayer` is set by then, so this stores the pending pick and `onTracksChanged` applies it. Or keep the clear and stop the restore depending on audio groups.

Other checks found nothing to report:
- **#1, order of calls:** `release()` removes `playerListener` before the old player goes away, so no stale `onTracksUpdated` or `applySubtitleSelection` can come from the old player after `prepare()`. A pick made after `prepare()` sets the pending pick again on the new player. `applySubtitleSelection` needs `Content` state, so it cannot run before `prepare()` on an episode switch or retry. `switchStream` (quality change, next stream candidate) does not call `prepare()`, so it keeps the pending pick as before. Every caller of `prepare()` resets `tracksRestoredForCurrentMedia` (`resetMediaSession`, `selectBufferPreset`, `toggleFastDns`).
- **#3, bibliographic code map:** all 20 ISO 639-2 codes whose bibliographic and terminology forms differ are mapped correctly. Region-suffixed input such as `ger-DE` is cut to `ger` before the lookup. Codes that still don't resolve to a name fall back to `subtitle.lang` in upper case, not to the mapped code, so the label text doesn't change. `canonicalSubtitleLanguage` has no callers outside `SubtitleLabels.kt`, so saved preferences are not affected.
- **#5:** every reader of `lastPanelOpener` needs a panel opened by `openPanel`, which writes the value first, so removing the reset is safe.
- **#4 and #6** change only tests and the plan document; neither adds an edge case.
