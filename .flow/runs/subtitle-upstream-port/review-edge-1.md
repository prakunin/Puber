### F1 [minor] Bibliographic ISO 639-2 codes (`ger`, `fre`, `chi`, `cze`, `dut`) skip the localized-name lookup
- Where: app/src/main/java/com/kino/puber/ui/feature/player/model/SubtitleLabels.kt:62-80
- Problem: `iso3Locales` is keyed by `Locale.isO3Language`, which only returns the terminology codes (`deu`, `fra`, `zho`, `ces`, `nld`). A bibliographic code never matches a key, so the lookup falls back to `Locale.forLanguageTag(canonical)`. The function's own KDoc says that path comes back untranslated. Media3's `normalizeLanguageCode` does map bibliographic codes, so the player resolves them but the picker label does not.
- Failure scenario: The API returns `lang = "ger"` and the app runs in Russian. I checked on the JVM with jshell: `forLanguageTag("ger").getDisplayLanguage(ru)` returns "German" in English, not "Немецкий". On Android ICU it may return "ger", which is then shown as "GER". Two rows (`ger` and `deu`) would read differently even though they are the same language. The codes AC-5 tests (`rus`, `eng`) are terminology codes, so the tests do not catch this.
- Fix: In `canonicalSubtitleLanguage`, map bibliographic codes to terminology codes before the lookup. The fixed set is about 20 codes: ger→deu, fre→fra, chi→zho, cze→ces, dut→nld, gre→ell, per→fas, rum→ron, slo→slk, arm→hye, geo→kat, may→msa, ice→isl, alb→sqi, baq→eus, bur→mya, mac→mkd, wel→cym, tib→bod. Another option is to build the map key from `Locale(it.language).isO3Language` and add the bibliographic aliases. Add `ger`/`fre` cases to `SubtitleLabelsTest`.
