## Directly relevant to startup-splash-preload / startup-settled-signal
1. PuberApp.kt:91 resolving ApiDomainInteractor on main builds ~half the DI graph, not just the keystore decrypt: two OkHttpClients (main data/di/modules.kt:58 + DoH bootstrap data/api/network/DnsOverHttpsFactory.kt:11), KinoPubApiClient (Ktor, 8 plugins, Json; KinoPubApiClient.kt:125-190), ContentCacheRepository + Room builder, WatchStateRepository via DetailsPrefetcher -> ItemDetailsRepository. WatchStateRepository then starts at once a full watch_state read and clearAllPending() write (WatchStateRepository.kt:49-56, 121-133) competing with startup I/O. Est. 50-150 ms on main on a weak box. Fix: Lazy/provider injection so initialize() needs only prefs, or move initialize() into the warm-up.
2. JSON decode on Main on the Home path: apiCall decodes with response.body<T>() in caller context (KinoPubApiClient.kt:1025-1026); ContentCacheRepository / CachedFeed have no flowOn/withContext; HomeVM.kt:320/322 starts 8+ section collectors on viewModelScope (Main), DetailsVM.kt:99-100 same. Only Room I/O hops to IO. Est. 30-60 ms per section on A53 during first Home frames. Fix: flowOn(Default) on ContentCacheRepository flows or decode under withContext(Default).
3. Same payload decoded 3-6 times per load (memory tier stores strings): lists ContentCacheRepository.kt:63->451, 71->394/398, 80 (queryNeedsRefetch decodes every card just to count; mergeItems decodes+re-encodes); details :220,232,236,240. Plus JSON-in-JSON-string encoding (CachedFeed.kt:210,360,567 with String.serializer()).
4. ensureLegacyRowsRemoved (ContentCacheRepository.kt:377-384) runs 6 DELETE ... LIKE :prefix||'%' (CachedPayloadDao.kt:28) on the first cache access of every process, under the Mutex all Home sections wait on; LIKE with a bound param cannot use the PK index -> full table scans. Done-flag is memory only. Fix: persist the flag / Room migration, or range query. cached_payload also grows unbounded (rows deleted only on read after 7 days, CachedFeed.kt:560-566).
5. Sequential requests: observeHotItems/observeFreshItems fetch movies then series (HomeInteractor.kt:58-59, 66-67), FreshSectionPager.kt:87-90 walks types sequentially. +150-400 ms per row on slow network; async/awaitAll.
6. DoH answers never cached (DnsOverHttpsFactory.kt:11-21 uses post(true), bootstrap client without Cache): +1 dns.google round trip per new connection/host, also for player CDN. Coil (PuberApp.kt:100-126, no fetcher -> own HttpClient/OkHttp), IntroDbAppApiClient.kt:31, TheIntroDbApiClient.kt:31 build separate HTTP stacks: up to 4 pools/dispatchers/TLS setups.
7. Baseline profile stale: app/src/main/generated/baselineProfiles last generated at 88cdf071 "Release 1.0.0" (2026-06-28, 573 commits ago), only root/auth/main/home + core classes, nothing for details/player although browseAndDetailsProfile exists. Not in docs/release.md.
8. R8 keep rules broader than old P5: -keepclassmembers com.kino.puber.** { public <init>(...); }, -keep kotlin.Metadata, androidx.security.crypto.**; coil-video kept but unused. AppCompat theme/dependency unused (MainActivity is ComponentActivity).
9. largeHeap (M5) also inflates Coil memory cache (PuberApp.kt:114, 15% of largeMemoryClass ~58-77 MB) and player buffer tier (DeviceBufferConfig.kt:134-153 picks top tier on 2 GB boxes).
10. Two prefs files read on main before first frame (AppLocale.wrap in attachBaseContext, TelemetryRuntime.start prefs.contains). Minor. No StrictMode in debug.
11. Timeouts 60 s connect / 120 s request + 3 retries on IOException (KinoPubApiClient.kt:163-167, ApiRetryPolicy.kt:33-64); reportIfDomainUnreachable only after last retry -> on a dead mirror the splash cap will fire long before failover.
