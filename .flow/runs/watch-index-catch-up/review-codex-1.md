- [major] app/src/main/java/com/kino/puber/data/repository/WatchStateRepository.kt:195-202 - `endSyncWindow()` publishes only a change that `syncChangeHeld` already holds at that moment. Room delivers the snapshot asynchronously, so the catch-up's own emission can arrive after its nested window closes. `onIndexChanged` then sees the outer walk's window still open, sets `syncChangeHeld`, and holds it until the walk ends. Scenario: a catch-up runs inside a parked walk's window and writes rows, its window closes before the snapshot emission, and filtered grids keep the old state for the rest of the walk, which can be minutes. This breaks the promise in the KDoc that a nested catch-up is not left waiting for the walk's end, and it hits AC-2 and AC-9. Without an outer window the late emission publishes normally, so only the nested case is affected. The new test uses an Unconfined collector, which hides this ordering.
- [minor] app/src/main/java/com/kino/puber/domain/interactor/watchstate/WatchStateSyncInteractor.kt:280-283 - `detailsCheckedIds += state.itemId` runs before `itemDetails.refresh`, and the ID is removed only on logout (line 426). A transient failure or cancellation of that one request therefore blocks every later catch-up from re-checking the series until the process restarts or the user logs out. Scenario: another client finishes a series, the Details request times out, and the title stays shown as unfinished across later catch-ups. Opening the title still refreshes it, and the per-run cap does not depend on this, so the impact is small. Record the ID only after a successful refresh, or remove it in `onFailure` and on cancellation.
