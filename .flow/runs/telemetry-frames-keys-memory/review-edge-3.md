### F1 [minor] Going Back to the tab host from a root screen names it `MainScreen`, because the binding is cleared when the host leaves composition
- Where: app/src/main/java/com/kino/puber/core/ui/navigation/component/FlowComponent.kt:588-591 (unbind in `onDispose`), NavTelemetry.kt:38-43, with the root runner's record at FlowComponent.kt:272
- Problem: the root `CurrentScreen` (FlowComponent.kt:492-505) composes only `navigator.lastItem`. Once a `RootPuberScreen` is pushed above `MainScreen`, `MainScreen.Content` leaves composition on the next frame. The `DisposableEffect` in `TabFlowNavigator` then runs `TabHostTelemetry.unbind`. On Back, the root runner pops and calls `recordNavCommand(event, navFrom, navChanged.lastItemOrNull)` in the same coroutine step, before `MainScreen` composes again and binds. `topOf(host)` therefore returns null, and `navClassOf` falls back to `MainScreen`. When the host composes again, the new binding writes nothing, so `Telemetry.screen` stays `MainScreen` until the next nav event. Frame windows (FrameProbe.kt:27), key events (KeyProbe.kt:127) and memory samples (MemoryProbe.kt:99) all carry that label until then. The round-2 build named the last tab here, which is correct for a tab root. So the most common return path now gets the container name. That is the case triage-2 #2 meant to fix ("Back to the host after a tab-local push"), and it is still not handled.
- Failure scenario: log on, Home tab, open a title. `DetailsScreen` is a `RootPuberScreen`, so it is pushed on the root navigator and `MainScreen` is disposed. Press Back. The result is `nav BACK from=Details to=Main` and `Telemetry.screen = MainScreen`, and the frames/keys/mem lines that follow are labelled Main instead of Home (or whatever screen was pushed inside the tab). `tabLocalPushThenRootBackNamesThePushedScreen` in NavTelemetryTest keeps a binding alive by hand, which this path never has, so it passes and cannot catch this.
- Fix: do not unbind on composition dispose. The host-identity check in `topOf` already stops a fresh host from reading a stale tab. Option 1: drop the `onDispose` unbind, or unbind only when a new host binds; that keeps one disposed tab `Navigator` reachable, and its stack is the one that comes back. Option 2: keep the unbind, and in the bind effect set `Telemetry.screen` to the top's class when the log is on and `Telemetry.screen == host.javaClass`. Either way, add a test that unbinds (as dispose does) and then records Back to the same host instance.
