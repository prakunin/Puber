### F1 [major] Leaving a nested flow by Back stores the screen you just left as the current screen
- Where: app/src/main/java/com/kino/puber/core/ui/navigation/component/NavTelemetry.kt:24 (new `Telemetry.screen = target`), which gets its value from FlowComponent.kt:271 (`recordNavCommand(event, navFrom, navigator.lastItemOrNull)`) after FlowComponent.kt:258-267 / 313-321
- Problem: `DeviceSettingsFlowScreen` is a nested `FlowComponent` with its own `AppRouter`. Its stack holds one screen (`DeviceSettingsScreen`). On `Command.Back` or `Command.FinishFlow`, `onBackWithNavigator` cannot pop that stack, so it pops the parent navigator instead. The nested runner then records `top = navigator.lastItemOrNull` from its own, unchanged stack. That value is the screen the user just left. Before this diff the error only affected the `nav.to` field. Now that value goes into the new `Telemetry.screen` holder. All four new event types read it through `ScreenScoped` (`frames`, `key`, `key_lat`, `mem`), so they keep that label until the next forward navigation.
- Failure scenario: open Settings (MainVM.kt:174 or the remote Settings hotkey), turn the Session log on, press Back. This is the normal way to start a recording. `DeviceSettingsVM.onBackPressed` calls the nested `router.back()`, `canPop()` is false, and the root pops the flow screen. `recordNav(BACK, DeviceSettingsScreen, DeviceSettingsScreen)` sets the holder to `DeviceSettingsScreen`. From then on, every `frames` window, key burst, `key_lat` and `mem` line on Main/Home is written with `scr` "DeviceSettings". That is the "Home window labelled with another screen" case the spec's D3 lists under "must not happen". No test covers a parent pop from a nested flow (F12 only checks PUSH and ACTIVITY).
- Fix: for Back and FinishFlow, record the top of the navigator that actually popped. For example, have `onBackWithNavigator` return the navigator it popped and pass `thatNavigator.lastItemOrNull` to `recordNavCommand`. Add a NavTelemetry or FlowComponent test where a one-item child stack pops its parent and assert that `Telemetry.screen` is the parent's new top.

### F2 [minor] After Back, the same tab content is labelled with the container's name instead of the tab's
- Where: app/src/main/java/com/kino/puber/core/ui/navigation/component/NavTelemetry.kt:23-24, with TabComponent.kt:111 and FlowComponent.kt:271
- Problem: a tab switch sets the holder to `telemetryClassOf(PuberTab)`, which is the tab's content class, e.g. Home. A root-flow Back from a pushed screen sets it to the root navigator's top, `MainScreen`, which is the container. The user sees the same Home content either way, but its frames, keys and memory lines are recorded under two names depending on how they got there. The QA report's D12 already shows `scr` values Home and Main side by side.
- Failure scenario: Home tab, scroll (frames `scr`=Home), open Details, press Back, scroll Home again. The new windows say `scr`=Main. Per-screen stats for Home are split, and Main looks like a screen of its own with its own jank numbers.
- Fix: when the recorded top is a tab host, map it to its current tab's `contentScreenClass` before writing the holder. Or leave the holder unchanged when the new top is the tab container and the tab did not change.
