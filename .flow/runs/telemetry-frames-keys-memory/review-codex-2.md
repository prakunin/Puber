- [minor] app/src/main/java/com/kino/puber/core/telemetry/TelemetryRuntime.kt:67-70 - The inline flush in `setEnabled(false)` makes `detachProbes(probesDetached = true)` skip the posted detach, and it runs ahead of an attach that is still queued. Scenario: `setEnabled(true)` posts the attach runnable, and `setEnabled(false)` runs on main before that runnable executes. The inline `detach` runs first. The queued `ActivityProbes.attach()` then starts the frame probe, memory callback and sampler while the sink is off. `attach` does not check the enabled state, and `sink.stop()` only calls `onStopped` on a storage failure, so nothing cleans up afterwards. Round 1 had the posted detach queued behind the attach. The window is narrow, because the click that enables telemetry usually drains the attach before the next input event. The cost is a leaked sampler and probe until the next toggle or expiry. Codex graded it P2/medium; I rate it minor. A fix is to guard the posted attach with an enabled check or a generation counter. A test would toggle on then off and drain the queue only afterwards.
- [minor] app/src/main/java/com/kino/puber/core/ui/navigation/component/NavTelemetry.kt:27-28 and TabComponent.kt:111 - `navClassOf` maps `MainScreen` to `TabHostTelemetry.content`, which is set only by `TabCommand.Open`.
