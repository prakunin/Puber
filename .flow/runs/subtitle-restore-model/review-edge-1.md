### F1 [minor] A row the restore picked as a substitute is saved as the viewer's choice on the next audio pick
- Where: app/src/main/java/com/kino/puber/ui/feature/player/vm/PlayerVM.kt:1867-1869 (`hasIntent = intendedSubtitleRow != null || subtitlePickedThisMedia`), with `restoreSubtitlePreference` at :618-619 where `applySubtitleSelection(persist = false)` sets `intendedSubtitleRow`.
- Problem: once the restore matches a row, it becomes `intendedSubtitleRow`, and the next save writes it with `toSubtitlePreference()`. Because of the tolerant filter (D7) and the manifest-preferring language rule, the restore can match a different row from the one saved (e.g. an API side-load with no readable label and `isForced == null` standing in for a labelled or forced manifest row). The first audio pick then replaces the stored identity, forced flag and label with the substitute's values, though the viewer never picked a subtitle in this media. AC-16 protects only the "matched nothing" case.
- Failure scenario: viewer picks manifest row "Russian Forced", saved `("rus", "subtitle:Russian Forced", true, "russian forced")`. Later session plays a stream without manifest subtitles (progressive / url.hls / CDN fallback); only the API side-load `rus` row exists (`forced = null`), passes the filter, rule 5 picks it. Viewer changes the voice-over: `SelectAudioTrack` saves `("rus", <apiUrl>, null, null)`. Next HLS session rule 1 (exact URL) picks the full API side-load; the forced manifest row never comes back.
- Fix: write the intent only after an explicit pick in this media: `val subtitle = if (subtitleRestoredForCurrentMedia && subtitlePickedThisMedia) intendedSubtitleRow.toSubtitlePreference() else interactor.getPreferredSubtitlePreference(params.itemId)`; otherwise pass the stored preference through. A rebuild keeps `subtitlePickedThisMedia`, so AC-11 (b) and rebuild cases still save the pick. VM test: stored manifest preference, stream with only the API row, restore matches it, `SelectAudioTrack`; the save carries the stored preference unchanged.
